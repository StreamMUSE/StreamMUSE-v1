## Restart And Source-Sync Handoff

Use the controller on H200. Do not run the raw argv above, delete PID manifests,
or stop a process by port/name. Stop refuses unverifiable identities; inspect
stale records and remaining exact descendants manually if that occurs.
Successful stops archive their records; logs append across restarts.

For renderer-only refresh, coordinate with the parent and stop it **before**
syncing source. Keep Qwen and MOSS warm:

```sh
ssh H200
cd /data/home/Andrew.Yang/StreamMUSE/deploy/rap_inference_20261111
python3 deploy_h200.py status render
python3 deploy_h200.py stop render
# Parent syncs final source into this root's repo, not a previous deployment.
python3 deploy_h200.py start render
python3 deploy_h200.py wait render --timeout 2400
python3 deploy_h200.py verify
```

For an explicitly requested full restart:

```sh
cd /data/home/Andrew.Yang/StreamMUSE/deploy/rap_inference_20261111
python3 deploy_h200.py stop render
python3 deploy_h200.py stop tts
python3 deploy_h200.py stop vllm
python3 deploy_h200.py start vllm
python3 deploy_h200.py start tts
python3 deploy_h200.py wait vllm --timeout 2400
python3 deploy_h200.py wait tts --timeout 2400
python3 deploy_h200.py start render
python3 deploy_h200.py wait render --timeout 2400
python3 deploy_h200.py verify
```

Do not rerun `prepare`: it intentionally refuses to overwrite an existing source
copy. `start` rechecks port availability, UUID mapping, and free memory. A wait
timeout leaves services running. The controller takes an exclusive lock, so
avoid simultaneous controller commands, including while `wait` is active.
`verify` issues a short real Qwen completion and saves fresh status/GPU evidence.

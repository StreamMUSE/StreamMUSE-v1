5 / Protocol

实验协议与执行流程

DownloadHF cache 与 gated model auth。
ServevLLM，按模型使用 1-GPU 或 2-GPU TP。
Smoke先跑 3 turns，验证裸答案格式。
Sweep按平衡顺序执行正式 cells。
Merge合并 per-turn 与 summary rows。
Filter过滤 pilot，生成 formal results。

正式统计口径

  • Greedy: temperature=0，每个 cell 1 run。
  • Normal: temperature=0.7, top_p=0.8，每个 cell 3 runs。
  • Oracle 只跑 all + greedy；APC-off 只跑 recent-32 / all。
  • 每轮保存 latency、tokens、strict / normalized 判分。

模型适配与运行约束

  • Qwen3 / Qwen3.6: enable_thinking=false。
  • gpt-oss: max_tokens=512，从 final content 判分。
  • Prompt 使用 Current number: N\nAnswer:。
  • Qwen235: 关闭 FlashInfer blockscale FP8 GEMM，显存占用设为 0.90。
3-turn smoke → balanced sweep → formal filtered summary

Recommendations

当前可执行建议

  • 需要稳健、非 reasoning、较好 accuracy/latency 平衡：优先看 Qwen3.6-27B。
  • 追求最高准确率且能接受 2 GPU：Qwen3-235B-FP8。
  • 接受 reasoning latency、追求正确率：gpt-oss-120b。
  • 不要默认 all history 最好；每个 task 都需要选 history window。
  • 报告 latency 时必须显式说明 APC 状态。
  • 如果 history 写入模型实际输出，要同时评估 self-history pollution。
